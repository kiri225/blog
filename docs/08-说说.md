# 08 — 说说

对照源码：`app/api/chatters.py`、`app/schemas/chatter.py`、`app/services/chatter_service.py`、`app/models/chatter.py`

前置：GitHub 登录 + 评论树已经做过，说说评论几乎是同一套。

---

## 学什么

- 数据库存 JSON 数组字符串（`images: TEXT default '[]'`），Schema 对外是 `list[str]`
- **静态路径 vs 动态路径**：`/admin`、`/comments` 必须在 `/{chatter_id}` 前面
- 一个 router 里混着「说说 CRUD」和「说说评论」

## 模型

### Chatter

| 字段 | 说明 |
|------|------|
| content | Markdown 正文 |
| images | TEXT，JSON 数组字符串 |
| mood | 心情，最长 20 |
| likes / comments_count | 计数 |
| status | `draft` / `published` |

### ChatterComment

与文章评论相同思路：`chatter_id`、`parent_id`、`github_user_id`、`content`、`ip`、`likes`、`status`

## 路由顺序（按对照源码的分组抄）

必须先注册下面这些，再注册 `/{chatter_id}`：

```
GET    /api/chatters
GET    /api/chatters/count
GET    /api/chatters/{chatter_id}/comments   # 注意：这条带 chatter_id，但比「裸 /{id}」更具体
POST   /api/chatters/comments
GET    /api/chatters/admin
POST   /api/chatters
GET    /api/chatters/comments/admin
PUT    /api/chatters/comments/{comment_id}/status
DELETE /api/chatters/comments/{comment_id}
POST   /api/chatters/comments/{id}/like
POST   /api/chatters/comments/{id}/unlike
GET    /api/chatters/{chatter_id}
POST   /api/chatters/{chatter_id}/like
POST   /api/chatters/{chatter_id}/unlike
PUT    /api/chatters/{chatter_id}
DELETE /api/chatters/{chatter_id}
```

对照文件里的注释：

> 管理接口必须在 `/{chatter_id}` 之前注册，否则 `"admin"` 会被当成 chatter_id

若 `chatter_id: int`，字符串 `admin` 其实会 422。表现仍是「管理列表打不开」，所以还是把 `/admin` 放前面。

## 接口规格

前缀：`/api/chatters`，tag：`说说`

### 公开

| 方法 | 路径 | 鉴权 | Query / Body | 响应 |
|------|------|------|--------------|------|
| GET | `/api/chatters` | 无 | page=1, size=20 (le=200) | 只返回 published |
| GET | `/api/chatters/count` | 无 | status 默认 `"published"` | `{count}` |
| GET | `/{id}` | 无 | | ChatterOut |
| GET | `/{id}/comments` | 无 | | 评论树 |
| POST | `/comments` | GitHub | ChatterCommentCreate | 新评论 |
| POST | `/{id}/like` `/unlike` | 无 | | `{likes}` |
| POST | `/comments/{id}/like` `/unlike` | 无 | | 评论 Out |

### ChatterCreate

| 字段 | 类型 | 默认 |
|------|------|------|
| content | str | 必填 |
| images | list[str] | `[]` |
| mood | str | `""` |
| status | str | `"draft"` |

### ChatterOut

`id, content, images: list[str], mood, likes, comments_count, status, created_at, updated_at`

落库时 `images` 用 `json.dumps`，读出用 `json.loads`。

### ChatterCommentCreate

`chatter_id: int`，`parent_id: int | None`，`content: str`

未登录 → 401 `请先登录 GitHub`

发表后记得 `chatter.comments_count += 1`（删除评论时要减回去）。

### 管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin` | status? + 分页，可看草稿 |
| POST | `""` | 管理员发说说 |
| PUT | `/{id}` | 管理员 |
| DELETE | `/{id}` | 管理员 |
| GET | `/comments/admin` | 审核说说评论 |
| PUT | `/comments/{id}/status` | Body `{status}` |
| DELETE | `/comments/{id}` | |

创建说说需要管理员。前台用户不能发说说，只能评论。

---

## 验收标准

1. 草稿说说：前台 GET `/api/chatters` 看不到，管理员 GET `/admin?status=draft` 看得到
2. 改为 published 后前台可见
3. `GET /api/chatters/admin` 返回 200，不是 422
4. images 传入 `["https://a.png"]`，GET 回来仍是数组不是字符串
5. 评论后 `comments_count` 加一；删评论后减一（最小 0）
6. 说说评论树与文章评论行为一致

---

## 易错点

- `GET /{id}/comments` 若写在 `/{id}` 后面通常仍能工作（更具体），但 `/admin` 一定不能放在 `/{id}` 后面去「碰运气」。
- `count` 的 status 默认值是 `"published"`，和文章 count 的「不传表示全部」不一样。
- images 空值：库里可能是 `""` 或 `'[]'`，`json.loads` 要兜底。
