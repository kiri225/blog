# 00 — 约定与架构

本阶段只读、不写代码。后面每个任务都按这里的约定实现。

对照源码：`app/main.py`、`app/api/router.py`、`app/deps.py`、`app/config.py`

---

## 学什么

- FastAPI 项目为什么要分层，而不是把所有逻辑写在 `main.py`
- `APIRouter` 如何把几十个接口拆开再汇总
- 依赖注入（`Depends`）如何复用 Session 和鉴权
- 两种用户体系：管理员 JWT vs GitHub 访客 JWT

---

## 分层

```
请求
  → api/          只负责路由：解析参数、调 service、声明 response_model
  → services/     业务：查询、校验、组装返回值、commit
  → models/       数据库表（SQLModel, table=True）
  → schemas/      请求体 / 响应体（Pydantic，不落库）
```

规则：

- `api/` 里尽量不要写 `session.exec(...)`。阶段 04 开始严格执行。
- `schemas/` 负责校验；`models/` 负责落库。两者不要混成一个类（对照项目就是分开的）。
- `deps.py` 只再导出公共依赖：`get_session`、`get_current_user`。

## 目录职责

| 文件 | 职责 |
|------|------|
| `app/main.py` | 创建 FastAPI、lifespan 建表、CORS、include_router、挂载静态目录 |
| `app/config.py` | 从 `.env` 读配置，禁止把密钥写进代码 |

| `app/utils/auth.py` | hash / verify 密码、签发 / 解析 JWT |

## 统一响应（对照项目的真实情况）

对照项目 **没有** 做成单一 envelope。实现时按模块对齐即可：

| 场景 | 形态 | 例子 |
|------|------|------|
| 大部分 CRUD | 直接返回 schema 对象 / 列表 | `[{id, name, ...}]` |
| 删除 | `{"ok": true}` | 文章、分类、评论 |
| 计数 | `{"count": N}` | posts/count、messages/count |
| 登录 / 当前用户 | `{code, message, data}` | 适配 Vue 管理后台 |
| 访客 | `{code, data}` 或 `{code, count}` | visitors |
| 上传 | `{url, orientation}` | upload/image |

错误统一用 `HTTPException(status_code=..., detail="中文说明")`。

## 鉴权约定

### 管理员

- Header：`Authorization: Bearer <token>`
- FastAPI：`HTTPBearer()` + `Depends(get_current_user)`
- Payload 至少包含：`sub`（username）、`admin`（bool）、`exp`
- 算法：HS256，过期 **72 小时**
- 写操作（POST/PUT/DELETE 后台资源）必须挂管理员依赖
- 读操作（前台列表、详情、点赞）默认公开

### GitHub 访客

- 另一套 JWT，payload：`sub`（github_user.id 字符串）、`login`、`type: "github"`
- 发评论 / 留言必须登录；解析失败返回 401「请先登录 GitHub」
- 未带 Token 时，部分接口用 `get_github_user_optional` 返回 `None`

两种 Token **不要混用**：管理员 Token 不能当 GitHub 用户发评论。

## 路由注册顺序（必读）

FastAPI 按**注册顺序**匹配路径。静态路径必须写在动态路径前面。

典型踩坑（阶段 05、08 会再强调）：

```
# 正确
GET /api/posts/count
GET /api/posts/detail/{post_id}
GET /api/posts/{slug}          # 放最后

# 错误：先注册 /{slug} 后，"count" 会被当成 slug
```

`chatters` 同理：`/admin`、`/comments/admin` 必须在 `/{chatter_id}` 之前。

## 分页约定

| 参数 | 默认 | 约束 |
|------|------|------|
| `page` | 1 | `ge=1` |
| `size` | 模块不同：文章 10，评论/留言 20 | `ge=1`，上限 100 或 200 |

偏移：`offset = (page - 1) * size`

列表排序：

- 文章：置顶优先，再按 `created_at` 降序
- 分类 / 相册 / 友链 / 收藏：按 `sort` 升序
- 评论顶层：`created_at` 降序；回复按时间升序挂到 `replies`

## 状态枚举

| 模块 | 字段 | 取值 |
|------|------|------|
| 文章 | `status` | `draft` / `published` / `archived` |
| 说说 | `status` | `draft` / `published` |
| 评论 / 留言 / 说说评论 | `status` | `pending` / `approved` / `rejected`（对照实现默认多为 `approved`） |
| 项目 | `status` | `developing` / `active` / `archived` |
| 友链 | `is_approved` | `true` 才在前台展示 |

## 环境变量

```env
DATABASE_URL=sqlite:///./kirameku.db
# 正式对照：postgresql://user:password@host:5432/kirameku

SECRET_KEY=换成足够长的随机字符串

CORS_ORIGINS=http://localhost:3000,http://localhost:5173

# 阶段 06 再填
GITHUB_CLIENT_ID=
GITHUB_CLIENT_SECRET=
FRONTEND_ORIGIN=http://localhost:3000

# 阶段 09 再填；学习阶段可先不配 OSS
OSS_ACCESS_KEY_ID=
OSS_ACCESS_KEY_SECRET=
OSS_BUCKET_NAME=
OSS_ENDPOINT=
OSS_CUSTOM_DOMAIN=
OSS_PREFIX=kirameku/
```

`config.py` 里：数据库和 `SECRET_KEY` 用 `os.environ["..."]` 强制必填；OAuth / OSS 可以有默认空字符串，等对应阶段再启用。
