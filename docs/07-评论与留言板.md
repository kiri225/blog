## 取 IP（两处复制即可，对照就是复制的）

```python
ip = request.headers.get("x-forwarded-for", "").split(",")[0].strip()
if not ip:
    ip = request.headers.get("x-real-ip", "")
if not ip:
    ip = request.client.host if request.client else ""
```

本地开发常常是 `127.0.0.1`。上线后才依赖反向代理的 `X-Forwarded-For`。

## 评论接口

前缀：`/api/comments`，tag：`评论`

### 公开

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/comments/post/{post_id}` | 无 | 该文章已审核评论树 |
| POST | `/api/comments` | GitHub | 发表 / 回复 |
| POST | `/api/comments/{comment_id}/like` | 无 | |
| POST | `/api/comments/{comment_id}/unlike` | 无 | |

### 管理

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/comments/admin` | 管理员 | 顶层评论分页，含 IP 和 replies |
| PUT | `/api/comments/{comment_id}/status` | 管理员 | 改审核状态 |
| DELETE | `/api/comments/{comment_id}` | 管理员 | |

### POST Body `CommentCreate`

| 字段 | 类型 | 必填 |
|------|------|------|
| post_id | int | 是 |
| parent_id | int \| null | 否，回复时填 |
| content | str | 是 |

**没有** nickname/email。用户信息来自 GitHub。

未登录 → 401 `请先登录 GitHub`  
`parent_id` 指向不存在的评论 → 404 `被回复的评论不存在`

默认 `status`：对照代码是 **`approved`**（直接显示）。你可以改成 `pending` 做审核练习，前台列表只返回 approved。

### CommentOut

```
id, post_id, parent_id, content, likes, status, created_at,
github_user: {id, login, avatar, bio} | null,
replies: CommentOut[]
```

前台组装树：先查出该 post 全部 approved，放进 `id → dict` 映射；再按 parent_id 挂到父节点的 replies，否则进 roots。

管理列表：只查 `parent_id IS NULL`，再递归把 replies 带上（含 IP）。

管理 Query：`status?, page=1, size=20 (le=100)`

### PUT status Body

`{"status": "approved"}` 或 `rejected` / `pending`

## 留言板接口

前缀：`/api/messages`，tag：`留言板`

留言是全站的，不挂文章。结构与评论几乎一样（也有 parent_id 树）。

### 公开

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/messages` | 无 | 已审核顶层 + replies，分页 |
| GET | `/api/messages/count` | 无 | 已审核顶层数量 |
| POST | `/api/messages` | GitHub | 留言 / 回复 |
| POST | `/api/messages/{msg_id}/like` | 无 | |
| POST | `/api/messages/{msg_id}/unlike` | 无 | |

Query：`page=1, size=20 (le=100)`

### 管理

| 方法 | 路径 | 鉴权 |
|------|------|------|
| GET | `/api/messages/admin` | 管理员 |
| GET | `/api/messages/admin/count` | 管理员 |
| PUT | `/api/messages/{msg_id}/status` | 管理员 |
| DELETE | `/api/messages/{msg_id}` | 管理员 |

管理 Query：`status?` 可空表示全部。

### MessageCreate

`content: str`，`parent_id: int | None = None`

### MessageOut

```
id, github_user_id, parent_id, content, ip, status, likes, created_at,
github_user, replies
```

前台 GET 也可以带 ip（对照 Out 有 ip 字段）。前台不展示即可。

发表成功对照返回的是 **dict**（`response_model=dict`），练习项目用 `MessageOut` 更干净。

---

## 路由顺序

`GET /admin`、`GET /admin/count` 必须写在 `/{msg_id}/...` 之前吗？

留言板动态段是 `/{msg_id}/like`，`admin` 不会被当成 int，FastAPI 会因类型不匹配跳过。但 **chatters 阶段** `/{chatter_id}` 若是 int，`admin` 同样不会匹配。对照仍把 `/admin` 放前面，养成习惯：静态路径一律先注册。

评论的 `/admin` 同理，必须在 `/{comment_id}` 类路径之前（如果有纯 `/{id}` GET）。对照评论没有 GET `/{id}`，但 PUT/DELETE 是 `/{comment_id}`，`admin` 不是 int，安全。仍建议 `/admin` 写上面。

---

## 验收标准

1. 未登录 POST 评论 → 401
2. GitHub Token POST 评论 → 出现在 `GET /post/{post_id}` 树里
3. 回复某条，出现在该节点 `replies` 里，而不是顶层再躺一条重复的
4. like 后 likes+1，unlike 到 0 不再减成负数
5. 管理员改 status 为 rejected，前台列表不再显示
6. 留言板分页：size=1 时只返回 1 条顶层，它的 replies 仍完整
7. 管理列表能看到 ip

---

## 易错点

- 组装树时，被回复的父评论若不在本次结果集（例如父是 rejected），子评论会变成「假根」。前台只查 approved 时要注意。
- `Message.ip` 在 Out 里有，Comment 前台 Out 默认不含 ip，管理才 `include_ip=True`。
- 不要再用 DATABASE.md 里的 nickname/email 字段，那是旧设计。
- 删除评论对照 **不级联删 replies**（SQL 脚本是 ON DELETE CASCADE，SQLModel create_all 未必带上）。删除前自己决定：先删子评论，或依赖数据库 CASCADE。
