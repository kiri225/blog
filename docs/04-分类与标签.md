## 学什么

- `APIRouter(prefix=..., tags=[...])`
- `response_model`：自动过滤多余字段、生成 OpenAPI
- Create / Update 两个 Schema：Update 字段全是 `T | None = None`
- `model_dump(exclude_unset=True)`：PATCH 式更新，只改传入的字段
- 写操作挂 `Depends(get_current_user)`，读操作公开

## 分类接口

前缀：`/api/categories`，tag：`分类`

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/categories` | 无 | 列表，按 `sort` 升序 |
| POST | `/api/categories` | 管理员 | 创建 |
| PUT | `/api/categories/{cat_id}` | 管理员 | 更新 |
| DELETE | `/api/categories/{cat_id}` | 管理员 | 删除，成功 `{"ok": true}` |

### CategoryCreate

| 字段 | 类型 | 默认 | 必填 |
|------|------|------|------|
| name | string | | 是 |
| slug | string | | 是 |
| description | string | `""` | 否 |
| sort | int | `0` | 否 |

### CategoryUpdate

以上字段全部 `可选 | None`。

### CategoryOut

`id, name, slug, description, sort, post_count, created_at, updated_at`

业务：

- `name`、`slug` 唯一。冲突时 400 即可（对照实现未必专门处理 unique，数据库会炸；练习项目建议 catch 后返回 400「分类已存在」）。
- 删除时：文章的 `category_id` 在 SQL 里是 `ON DELETE SET NULL`。用 `create_all` 时确认外键行为，或删除前把文章的 category_id 置空。
- `post_count` 本阶段保持 0，阶段 05 写文章时再维护。

## Service 习惯写法

```python
def update_category(session, cat_id, data: CategoryUpdate) -> Category:
    cat = session.get(Category, cat_id)
    if not cat:
        raise HTTPException(404, "分类不存在")
    for k, v in data.model_dump(exclude_unset=True).items():
        setattr(cat, k, v)
    cat.updated_at = datetime.now()
    session.add(cat)
    session.commit()
    session.refresh(cat)
    return cat
```

`exclude_unset=True` 很关键：客户端只传 `{ "sort": 1 }` 时，不要把 name 覆盖成 None。

## 验收标准

1. Swagger 里分类、标签两组 tag 都出现
2. GET 列表无需登录
3. POST 无 Token → 失败
4. 创建两个分类，GET 能按 sort 排序
5. PUT 只改 description，name/slug 不变
6. DELETE 后再 GET，该条消失
7. 不存在的 id → 404

## 易错点

- 路径参数名 `cat_id` / `tag_id` 只是函数参数名，URL 里就是整数 id。
- `response_model=list[CategoryOut]` 需要 SQLModel 实例字段名和 Out 对得上。如果 Out 有 `updated_at` 而表里忘了这个字段，会校验失败。
- 注册 router 时不要加重复 prefix。router 自己已经有 `prefix="/api/categories"`，`include_router` 不要再写一遍。
