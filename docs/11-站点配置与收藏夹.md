# 11 — 站点配置与收藏夹

对照源码：

- `app/api/site_config.py`、`app/api/bookmarks.py`
- `app/schemas/site_config.py`、`app/schemas/bookmark.py`
- `app/services/site_config_service.py`、`app/services/bookmark_service.py`

前置：管理员 JWT。配置是 KV；收藏夹是「分类套站点」的嵌套结构。

---

## 学什么

- 站点配置：一张表当字典用，value 存 JSON 字符串
- 前台 `GET /` 返回 `{key: 解析后的值}`，管理端 `/list` 返回完整行
- 路由：`GET /list` 必须在 `GET /{key}` 之前，否则 `list` 会当成 key
- 嵌套 response_model：`BookmarkFull = Category + sites[]`
- 又一次 JSON 数组字段：`platforms`

## 站点配置

前缀：`/api/site-config`，tag：`站点配置`

路径是 **`site-config`**（连字符）。

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/site-config` | 无 | 全部配置 → 一个 dict |
| GET | `/api/site-config/list` | 管理员 | 完整列表（含 id、description） |
| GET | `/api/site-config/{key}` | 无 | 单个 value（JSON 解析后） |
| POST | `/api/site-config` | 管理员 | 新建 key |
| PUT | `/api/site-config/{key}` | 管理员 | 更新 value |
| PUT | `/api/site-config` | 管理员 | Body 为 dict，批量更新 |
| DELETE | `/api/site-config/{key}` | 管理员 | |

### GET `/` 前台形态

value 能 `json.loads` 就解析，否则当普通字符串。

```json
{
  "site_title": "Kirameku",
  "site_description": "煌めく — 一个个人博客",
  "icp_number": ""
}
```

对照种子里 value 是 `'"Kirameku"'` 这种 JSON 字符串，所以 loads 之后是不带引号的字符串。

### GET `/list`

```json
[
  {
    "id": 1,
    "key": "site_title",
    "value": "\"Kirameku\"",
    "description": "站点标题",
    "updated_at": "..."
  }
]
```

### POST Body

`key: str`，`value: str = ""`，`description: str = ""`

key 已存在 → 400 `配置 {key} 已存在`

### PUT `/{key}` Body `SiteConfigUpdate`

`value: str`（必填），`description: str = ""`

### PUT `/` 批量

Body 例：`{"site_title": "新标题", "icp_number": ""}`

对照 service 会按 key 更新已有行。练习项目：已有则改 value，没有可选择跳过或创建。

## 收藏夹

前缀：`/api/bookmarks`，tag：`收藏夹`

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/bookmarks` | 无 | 分类数组，每项带 `sites` |
| GET | `/api/bookmarks/categories` | 无 | 仅分类 |
| POST | `/api/bookmarks/categories` | 管理员 | |
| PUT | `/api/bookmarks/categories/{cat_id}` | 管理员 | |
| DELETE | `/api/bookmarks/categories/{cat_id}` | 管理员 | 建议级联删站点 |
| GET | `/api/bookmarks/sites` | 无 | Query `category_id?` |
| POST | `/api/bookmarks/sites` | 管理员 | |
| PUT | `/api/bookmarks/sites/{site_id}` | 管理员 | |
| DELETE | `/api/bookmarks/sites/{site_id}` | 管理员 | |

### BookmarkCategoryCreate

`name: str`，`icon=""`，`description=""`，`sort=0`

### BookmarkSiteCreate

| 字段 | 类型 | 默认 |
|------|------|------|
| category_id | int | 必填 |
| name | str | 必填 |
| url | str | 必填 |
| icon | str | `""` favicon URL |
| description | str | `""` |
| platforms | list[str] | `[]` 如 `["web","ios"]` |
| sort | int | `0` |

### BookmarkFull

CategoryOut 的字段 + `sites: BookmarkSiteOut[]`

前台 GET `/api/bookmarks` 按分类 `sort` 排，每个分类下的站点也按 `sort` 排。

## 验收标准

1. `GET /api/site-config/list` 无 Token 失败；`GET /api/site-config` 成功
2. `GET /api/site-config/list` 不会变成查找 key=`list`
3. PUT 某个 key 后，前台 dict 里对应值变化
4. 创建分类「工具」和两个站点，`GET /api/bookmarks` 结构为 `[{ name, sites: [...] }]`
5. `platforms` 往返仍是数组
6. 删分类后其站点不再出现（或删分类返回 400 提示先删站点——二选一，文档化你的选择）

---

## 易错点

- `GET /{key}` 会吃掉 `list`，所以 `/list` 必须先注册。对照 `site_config.py` 就是这个顺序。
- 批量更新是 `PUT ""` 和 `PUT /{key}` 共存。FastAPI 可以，注意别都写成 GET。
- `value` 在库里永远是字符串。前台接口负责 loads；管理 list 对照返回的是**未解析**的原始字符串。
- bookmark 的 `icon` 分类上是短图标名（50），站点上是 URL（500）。
