# 05 — 文章系统

对照源码：`app/api/posts.py`、`app/schemas/post.py`、`app/services/post_service.py`

前置：分类、标签 CRUD 可用。这是本项目最核心的模块。

---

## 学什么

- 查询参数 `Query(1, ge=1)` 与可选筛选
- 路径参数：`{slug}` vs `{post_id}`
- **静态路由必须注册在动态路由前面**
- 多对多：`PostTag` 中间表，创建文章时按名字找/建标签
- 冗余计数：`category.post_count`、`tag.post_count`
- `response_model` 列表用 `PostOut`，详情用 `PostDetail`（多 `content`）
- 部分更新 + 自动字段（字数、阅读时间、published_at）

---

## 任务清单

- [ ] Schema：PostCreate / PostUpdate / PostOut / PostDetail
- [ ] Service：列表筛选分页、详情（按 slug 增加 views）、CRUD、点赞、同步标签、更新计数
- [ ] API 全部接口，注意路由顺序
- [ ] 创建已发布文章时写入 `published_at`
- [ ] slug 访问详情时 `views += 1`

---

## 路由顺序（必须按此注册）

```
GET    /api/posts                 列表
GET    /api/posts/count            计数
GET    /api/posts/detail/{post_id} 后台按 id 取详情（不增加浏览量）
GET    /api/posts/{slug}          前台按 slug（增加浏览量）
POST   /api/posts                 创建（管理员）
PUT    /api/posts/{post_id}       更新（管理员）
POST   /api/posts/{post_id}/like
POST   /api/posts/{post_id}/unlike
DELETE /api/posts/{post_id}      删除（管理员）
```

如果先写 `/{slug}`，再写 `/count`，访问 `/api/posts/count` 会 404 或去查 slug=`count` 的文章。

## 接口规格

前缀：`/api/posts`，tag：`文章`

### GET `/api/posts`

鉴权：无

Query：

| 参数 | 类型 | 默认 | 约束 | 说明 |
|------|------|------|------|------|
| status | string? | 无 | | `draft` / `published` / `archived` |
| category | string? | 无 | | **分类 slug**，不是 id、不是 name |
| tag | string? | 无 | | **标签 slug** |
| page | int | 1 | ge=1 | |
| size | int | 10 | ge=1, le=200 | |

排序：`is_pinned DESC, created_at DESC`。

响应：`PostOut[]`（**不含 content**）

### GET `/api/posts/count`

Query：`status?`

响应：`{"count": 3}`

### GET `/api/posts/detail/{post_id}`

按主键取，含 content。**不**增加 views。给后台编辑页用。

不存在 → 404 `文章不存在`

### GET `/api/posts/{slug}`

按 slug 取，含 content。每次请求 `views += 1` 并 commit。

### POST `/api/posts`

鉴权：管理员

Body `PostCreate`：

| 字段 | 类型 | 默认 |
|------|------|------|
| title | str | 必填 |
| slug | str | 必填，全站唯一 |
| description | str | `""` |
| content | str | `""` Markdown |
| cover | str | `""` 封面 URL |
| category_id | int \| null | `null` |
| tags | list[str] | `[]` **标签名字**，不是 id |
| status | str | `"draft"` |
| is_pinned | bool | `false` |
| reading_time | int | `0` |
| word_count | int | `0` |

响应：`PostOut`（可含 content 视你的 Out 定义；对照 Out **不含** content）

### PUT `/api/posts/{post_id}`

Body `PostUpdate`：全部可选。`tags is not None` 时才同步标签（传 `[]` 表示清空）。

### POST like / unlike

公开。响应：`{"likes": N}`。unlike 时 likes 最小为 0。

### DELETE `/api/posts/{post_id}`

管理员。删文章后重算该分类和全部标签的 post_count。`{"ok": true}`

---

## 响应字段

### PostOut

```
id, title, slug, description, cover,
category: str     # 分类 name，没有则为 ""
tags: list[str]   # 标签 name 列表
status, is_pinned, views, likes, word_count, reading_time,
published_at, created_at, updated_at
```

注意：库里是 `category_id`，对外是 **分类名字符串**。列表接口不要把 `category_id` 直接丢给前台。

### PostDetail

`PostOut` + `content`

## 业务规则

### 标签同步 `_sync_tags`

1. 删除该 post 的全部 PostTag
2. 对每个名字 `strip`，空则跳过
3. 按 **name** 查找 Tag；没有则创建，`slug = name.lower().replace(" ", "-")`
4. 插入 PostTag
5. 重算所有 Tag 的 `post_count`

### 分类计数

对该 `category_id`：`post_count = COUNT(post WHERE category_id=?)`

更新文章换分类时，**旧分类和新分类都要重算**。

### 字数与阅读时间

创建/更新时若有 content：

- 未手动传 `word_count`：`len(content)`
- 未手动传 `reading_time`：`max(1, word_count // 300)`

### 发布时间

`status == "published"` 且 `published_at` 为空 → 设为现在。草稿不要写 published_at。

---

## 验收标准

1. 创建分类「随笔」slug=`notes`，再创建带该分类、两个标签的已发布文章
2. `GET /api/posts?status=published&category=notes` 能筛到
3. `GET /api/posts?tag=<标签slug>` 能筛到
4. 连续两次 `GET /{slug}`，views 从 n 变成 n+2
5. `GET /detail/{id}` 不增加 views
6. `GET /count` 返回数字
7. 更新 tags 为新名字，旧标签 post_count 下降，新标签出现
8. 无 Token 创建文章失败；有 Token 成功
9. 访问 `/api/posts/count` **不会**被当成 slug

## 易错点

- 筛选参数 `category` / `tag` 是 slug，Create 里的 `tags` 是 name 列表。两边不一样。
- `PostCreate` 要用 `model_dump(exclude={"tags"})` 再 `Post(**)`，因为表上没有 `tags` 列。
- slug 唯一冲突应 400 或 500；练习项目建议查重后 400「slug 已存在」。
- 列表不要 `selectinload` 也行，对照是手动查 Category/Tag 再拼 dict。
