# 13 — 小说模块（规划）

本文件是**尚未实现**的规划，不是 `docs/modules/` 交接文档。代码落地后另写 `docs/modules/12-小说.md`，并以代码为准。

前置：管理员 JWT（01）、GitHub 访客登录（04）、图片上传（08）。写法跟现有仓库：`Result` 信封 `code=200`、文件 PascalCase、`api` 不写 `session.exec`。

---

## 1. 要做成什么样

个人博客上放连载小说。

| 角色 | 能做什么 |
|------|----------|
| 管理员 | 后台增删改**小说**和**章节**；可存草稿 |
| 访客 | 不登录也能看到书单、封面、简介、目录 |
| GitHub 登录访客 | 才能打开章节**正文**（「看小说」） |

管理员 Token 和 GitHub Token **不能混用**。后台编辑走管理员 JWT；前台阅读走 GitHub JWT。

### 1.1 为什么拆成「书 + 章节」

只做一篇 Markdown（像文章）也能交差，但连载没法按章更新、阅读页也无法「下一章」。第一期就做两张表：`novel`、`novel_chapter`。删小说时**级联删除**其下全部章节。

### 1.2 本期不做

- 小说评论 / 打赏 / 书架 / 阅读进度落库
- 付费章节、VIP
- 独立分类体系（不复用文章 `category`，避免和博客分类搅在一起）
- 仪表盘里加 `novels` 计数（可第二期再加）

以后要加，在本文件末「后续」里扩，不要第一期塞进去。

## 2. 鉴权（必须先钉死）

和评论/留言同一套访客校验：路由用 `get_github_user_optional` 读 Header，service 里没有用户则 **401** `请先登录 GitHub`。不要对访客接口用 `HTTPBearer()`（那套缺 Token 是 **403**）。

| 场景 | 鉴权 | 失败 |
|------|------|------|
| 前台书单、简介+目录 | 无 | — |
| 前台章节正文 | GitHub JWT | 无 Bearer / 非 github / 过期 → **401** `请先登录 GitHub` |
| 后台 CRUD、按 id 取含正文 | 管理员 JWT | 无 Token → **403**；无效 → **401** `无效的令牌` |

未登录打开阅读页：前端先跳 GitHub 登录（现有 `/api/auth/github/login`），回来带 token 再请求正文。后端只认 Header，不认 cookie。

**草稿**：前台列表/详情只返回 `published`。草稿只有管理员 `/admin` 和 `GET /detail/{id}` 看得到。未发布章节即使已登录 GitHub 也 404（避免目录泄漏草稿标题——目录接口同样只给 published 章节）。

## 3. 表设计

### 3.1 `novel`

| 列 | 类型 | 说明 |
|----|------|------|
| id | int PK | |
| title | str(200) | 书名 |
| slug | str(200) 唯一 | 前台路径 `/novels/{slug}` |
| description | str(500) 默认 `""` | 简介，列表用 |
| cover | str 默认 `""` | 封面 URL，走 `POST /api/upload/image` |
| status | str(20) | `draft` / `published` / `archived` |
| is_featured | bool 默认 false | 精选 |
| sort | int 默认 0 | 越小越靠前；同 sort 再按 `updated_at` 降序 |
| chapter_count | int 默认 0 | 已发布章节数，章节增删改时回写 |
| word_count | int 默认 0 | 已发布章节字数之和 |
| published_at | datetime? | 首次变为 published 时写入 |
| created_at / updated_at | datetime | |

类名 `Novel` → 表名 `novel`。

### 3.2 `novel_chapter`

| 列 | 类型 | 说明 |
|----|------|------|
| id | int PK | |
| novel_id | FK → novel.id | 小说删除时先删章节 |
| number | int | 章序号，同一本内唯一，从 1 起；前台「第 n 章」 |
| title | str(200) | 章标题 |
| content | text 默认 `""` | Markdown 正文 |
| word_count | int 默认 0 | 按 `len(content)`，创建/更新时算 |
| status | str(20) | `draft` / `published` |
| created_at / updated_at | datetime | |

`__tablename__ = "novel_chapter"`。建议唯一约束 `(novel_id, number)`。

`number` 冲突 → 400 `章节序号已存在`。

## 5. 接口

前缀：`/api/novels`。成功一律 `{code: 200, message, data}`。JSON **snake_case**。

### 5.1 一览

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/novels` | 无 | 已发布书单，不含章节正文 |
| GET | `/api/novels/count` | 无 | 已发布本数 |
| GET | `/api/novels/admin` | 管理员 | 可按 status 筛，含草稿 |
| POST | `/api/novels` | 管理员 | 创建书 |
| GET | `/api/novels/detail/{novel_id}` | 管理员 | 按 id，含草稿；给编辑页 |
| PUT | `/api/novels/{novel_id}` | 管理员 | 只改传入字段 |
| DELETE | `/api/novels/{novel_id}` | 管理员 | 先删章节再删书 |
| GET | `/api/novels/{slug}` | 无 | 简介 + **已发布**目录（无 content） |
| GET | `/api/novels/{slug}/chapters/{number}` | GitHub | **正文**；未登录 401 |
| POST | `/api/novels/{novel_id}/chapters` | 管理员 | 新增一章 |
| PUT | `/api/novels/chapters/{chapter_id}` | 管理员 | 改章节 |
| DELETE | `/api/novels/chapters/{chapter_id}` | 管理员 | 删一章并回写计数 |

读用 **slug**（+ 章 `number`），写用 **id**。和文章一样。

### 5.2 路由顺序（必须）

静态路径写在 `/{slug}` 前面。

```
GET    /api/novels
GET    /api/novels/count
GET    /api/novels/admin
POST   /api/novels
GET    /api/novels/detail/{novel_id}
POST   /api/novels/{novel_id}/chapters
PUT    /api/novels/chapters/{chapter_id}
DELETE /api/novels/chapters/{chapter_id}
GET    /api/novels/{slug}
GET    /api/novels/{slug}/chapters/{number}
PUT    /api/novels/{novel_id}
DELETE /api/novels/{novel_id}
```

`admin`、`count`、`detail`、`chapters` 都不能落在裸 `/{slug}` 之后去碰运气。

### 5.3 书单 `NovelListResponse`（无正文、无章节）

`id, title, slug, description, cover, status, is_featured, sort, chapter_count, word_count, published_at, created_at, updated_at`

前台 GET `/` 固定 `status=published`，按 `sort` 升序再 `updated_at` 降序。Query：`page=1, size=20 (le=100)`。

### 5.4 前台详情 `NovelPublicResponse`

列表字段 + `chapters: {id, number, title, word_count, created_at}[]`  
目录只含 `published` 章，按 `number` 升序。 **没有 content。**

不存在或未发布 → 404 `小说不存在`（草稿不要用另一句文案，避免被枚举）。

### 5.5 章节正文 `ChapterDetailResponse`

`id, novel_id, novel_slug, novel_title, number, title, content, word_count, created_at, updated_at`  
另加便于翻页的 `prev_number` / `next_number`（int 或 `null`，只在已发布章之间跳）。

未登录 → 401 `请先登录 GitHub`。  
书或章不存在 / 未发布 → 404 `章节不存在`。

### 5.6 创建书 `CreateNovelRequest`

| 字段 | 必填 | 默认 |
|------|------|------|
| title, slug | 是 | |
| description, cover | 否 | `""` |
| status | 否 | `draft` |
| is_featured | 否 | `false` |
| sort | 否 | `0` |

slug 冲突 → 400 `slug 已存在`。非法 status → 400 `状态不合法`。首次 `published` 写 `published_at`。

### 5.7 更新书 `UpdateNovelRequest`

全部可选。不传不改。slug 若改则仍须唯一。

### 5.8 创建章 `CreateChapterRequest`

`number` 必填；`title` 必填；`content` 默认 `""`；`status` 默认 `draft`。

小说不存在 → 404 `小说不存在`。同一本 `number` 冲突 → 400 `章节序号已存在`。

落库后按该本**已发布**章节重算 `chapter_count`、`word_count`，更新 `novel.updated_at`。

### 5.9 更新章 / 删除

更新全部可选。删除成功 `{code: 200, message: "删除成功", data: null}`。章不存在 → 404 `章节不存在`。

删书：先删该本全部章节再删 `novel`，文案同样「删除成功」。

### 5.10 管理端取书

`GET /detail/{novel_id}` 返回书字段 + 全部章节（含草稿、含 content），不增加任何浏览量。给编辑页一次拉齐。

## 6. 前台页面（建议）

路径按现有前台习惯用 slug，不强制框架。

| 页 | 路由 | 行为 |
|----|------|------|
| 书单 | `/novels` | `GET /api/novels`，卡片：封面、书名、简介、章数 |
| 简介+目录 | `/novels/{slug}` | `GET /api/novels/{slug}`；章标题可点进阅读页 |
| 阅读 | `/novels/{slug}/{number}` | 先 `GET /api/auth/github/me` 或直接拉章节；401 则引导 GitHub 登录，回来再请求 |
| 登录回调 | 已有 `/auth/callback?token=` | 把 GitHub JWT 存下来，Header `Authorization: Bearer` |

未登录时目录仍展示；点进章节再拦。不要整站书单也 401，否则「展示小说」不成立。

封面：`next/image` 或普通 `img`，URL 规则与相册相同（`/uploads/...` 或 OSS）。

## 9. 验收

1. 无 Token `GET /api/novels` 200，只有 published  
2. 无 Token `GET /api/novels/{slug}/chapters/1` → **401** `请先登录 GitHub`  
3. 管理员 Token 调该阅读接口仍 401（payload 没有 `type: github`）  
4. GitHub Token 可取已发布章正文；`content` 为 Markdown 字符串  
5. 草稿书、草稿章前台 404  
6. 创建 slug=`demo-novel` 后 `GET /api/novels/demo-novel` 有目录、无 content  
7. 同一本重复 `number` → 400 `章节序号已存在`  
8. 删书后其章节 GET 404；`chapter_count` 与已发布章一致  
9. `GET /api/novels/admin` 无 Token → 403  
10. `/count`、`/admin` 不会被当成 slug  

---

## 10. 易错点

- 访客缺 Token 必须是 **401 请先登录 GitHub**，不要 403。  
- 管理员 JWT 不能当阅读凭证。  
- `GET /{slug}` 放在 `/admin`、`/count`、`/detail`、`/chapters` 之后。  
- `chapter_count` / `word_count` 只统计 **published** 章。  
- 封面不接文件流，只存 URL。  
- 成功 `code=200`，不要写成学习稿里的 0。
