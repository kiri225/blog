## 访客接口

前缀：`/api/visitors`，tag：`访客记录`

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/visitors` | 无 | 最近访客分页 |
| GET | `/api/visitors/count` | 无 | 总数 |
| GET | `/api/visitors/location` | 无 | 当前请求者的地理（不落库） |
| POST | `/api/visitors/record` | 无 | 前端进入页面时打一次 |
| DELETE | `/api/visitors/{visitor_id}` | 无* | 删一条 |
| DELETE | `/api/visitors` | 无* | 清空 |

\* 对照实现删除/清空 **没有** 挂管理员依赖。练习项目建议加上 `get_current_user`，避免被随便清空。规格上你可以升级安全性。

### POST `/record`

从请求取：

- IP：同评论那套 X-Forwarded-For
- path：`X-Path` Header，没有则为 `""`
- ua：`User-Agent`

然后查地理（缓存按 IP）、解析 UA，插入 Visitor。

响应：`{"code": 0, "message": "ok"}`

### GET `/`

Query：`page=1, size=20 (le=100)`

响应：`{"code": 0, "data": [ Visitor, ... ]}` 按 `created_at` 降序。

### GET `/count`

`{"code": 0, "count": N}`

### GET `/location`

只算当前 IP 的 geo，不写库。`{"code": 0, "data": {...}}`

## Visitor 字段

| 字段 | 说明 |
|------|------|
| ip | |
| path | 访问路径 |
| user_agent | 原始 UA |
| city / region / country / district | 地理 |
| org / asn | 组织与 ASN |
| is_mobile / is_proxy / is_hosting | ipapi 布尔 |
| browser / os / device_type | 解析结果 |
| created_at | |

地理对照用 `http://ipapi.co/{ip}/json`。本地 `127.0.0.1` 通常没有有效地理，返回空字符串即可，不要让整个 record 失败。

学习阶段可跳过真实 HTTP：geo 全填空，仍能练仪表盘。

## 仪表盘

前缀：`/api/dashboard`，tag：`仪表盘`

### GET `/api/dashboard/stats`

鉴权：对照 **没有** 登录要求。练习可加管理员依赖。

响应结构：

```json
{
  "counts": {
    "posts": 0,
    "drafts": 0,
    "categories": 0,
    "tags": 0,
    "comments": 0,
    "messages": 0,
    "visitors": 0
  },
  "post_trend": [{"date": "2026-08-01", "count": 0}],
  "visitor_trend": [{"date": "2026-08-01", "count": 0}],
  "category_distribution": [{"name": "随笔", "value": 3}],
  "browser_distribution": [{"name": "Chrome", "value": 10}]
}
```

规则：

- `posts`：`status == published` 的数量
- `drafts`：`status == draft`
- `post_trend`：近 30 天，按 `published_at` 的日期分组，只计 published
- `visitor_trend`：近 30 天按 `created_at` 分组
- 两个 trend 都要 **补全 30 个日期**，没有数据的日子 count=0
- `category_distribution`：`post_count > 0` 的分类
- `browser_distribution`：按 `Visitor.browser` 分组，空显示「未知」

## 验收标准

1. 连续 POST `/record` 两次，count 增加 2（对照不去重；练习若做去重请写进文档）
2. GET 列表最新的在前面
3. `/location` 对本地 IP 不 500
4. dashboard 的 `post_trend` 长度恒为 30
5. 发布一篇文章后 `counts.posts` 增加（published 才算）
6. 清空后 count 为 0（若你给删除加了鉴权，无 Token 应失败）

## 易错点

- `GET /count`、`GET /location` 写在 `/{visitor_id}` 前面。
- `DELETE ""` 清空和 `DELETE /{id}` 共存，注意不要用错。
- PostgreSQL 用 `func.date(col)`；SQLite 日期函数不一样。学习用 SQLite 时可用 `func.strftime('%Y-%m-%d', Visitor.created_at)` 或在 Python 里分组。
- 第三方 API 失败时 record 仍应成功，只是城市为空。不要把整个请求 500。
- `main.py` 里还有 `GET /api/health` 和 `GET /api/routes`，做完本阶段后确认它们还在。
